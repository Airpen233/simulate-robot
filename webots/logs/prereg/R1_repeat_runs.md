## 成功判据（跑之前定死，不得放宽）

### 单次运行「通过」的定义

必须**同时**满足：

1. `result = reached`（Supervisor 真值行存在）
2. `true_error_m ≤ 0.03`（3 cm 标准，沿用历史口径）
3. `min_clearance_m > 0`（几何通道，新增）

**第 3 条是本轮新增的。** 加它之后，历史上「碰撞 0」的 15 个 run 会从「通过」变成「不通过」。

### 场景级「稳定」的定义

同一（场景, 种子）跑 3 次：

- **稳定通过**：3/3 满足上述三条
- **稳定失败**：0/3 满足
- **不稳定**：1/3 或 2/3 满足

不稳定样本**不比稳定失败更差**，但必须单独列出——它说明该方法对该场景没有确定行为。

### 执行情况

| 失败重跑 | 11 次（并发冲突，见下） |

**踩坑**：第一次尝试时并行启动了两个 `run_avoid.ps1`，Webots 无法同时运行两个实例，后启动的批次 `WEBOTS_EXIT_CODE=-1`、1.6 秒退出、零日志。11 次运行作废重跑。**补跑必须严格串行。**

### 核心结果：17 个场景全部 N=3，不确定性为零

```
场景总数: 17    N 全部 = 3
  稳定通过 STABLE_PASS:  7
  稳定失败 STABLE_FAIL: 10
  不稳定   UNSTABLE:     0     ← 一次都没有
```

**17/17 场景的三次重复，真值误差完全相同（精确到 0.00001 m）；间隙也完全相同。**

更强的证据：`random_seed_3` 的三份 Supervisor 日志，**去掉 header 后逐字节相同**（62 行 POSE 完全一致）。

### 按新三条件判据复算

判据：`reached` + `true_error ≤ 3 cm` + `min_clearance > 0`

```
稳定通过率 7/17 = 41.2%
```

对比旧口径（只看误差 ≤3cm，不看间隙）：11/17 = 64.7%

**差额 4 个场景，全部是因为几何间隙 ≤ 0 而被判失败**（front、random_seed_1、random_seed_2、random_seed_3）。这是新增第 3 条判据的直接效果，不是算法退化。

### 假设验证

| 假设 | 预测 | 实际 | 判定 |
|---|---|---|---|
| H1 结果可复现 | 落在同一量级 | **逐字节完全相同**，远超预期 | ✅ 成立（且比预期强） |

H2、H3 的机制解释被证实为**确定性缺陷**，不是偶发噪声。

### 预登记时没想到的发现

我预登记时假设「重复实验能暴露不稳定性」。**这个假设本身错了。**

三次重复零方差，说明这个仿真链路是**完全确定性**的：
- 固定时间步（32 ms）
- 无随机数注入
- 无传感器噪声建模
- 无外部扰动

**所以「跑 3 次」在当前设置下等价于「跑 1 次」。**

### 这意味着什么（必须诚实说明）

1. **补重复实验这个方案，前提是错的。** 我按 CoRL/RSS 的「多种子」经验设计，但那些方法针对的是**有随机性的训练过程**（初始化、数据顺序、GPU 非确定性）。本项目不训练，仿真步进完全确定。
2. **成本白花了**：34 次运行 ≈ 20 分钟，信息量约等于 0（因为结果必然相同）。
3. **但产出不是零**：它证明了确定性，这本身是重要事实——意味着**以后任何改动都可以精确归因**，改了什么，结果变化就一定是改动导致的，没有噪声干扰。
4. **真正需要的多样性不是"同场景重复"，而是"更多不同场景"。** 要从 17 个场景扩到 50+、100+ 个，才有统计意义。

### 对工作流的修正

`EXPERIMENT_WORKFLOW.md` §1「双层随机协议」需要改：当前项目的随机性**只存在于场景层**（障碍物布局），执行层是确定的。所以：

- ❌ 每场景跑 N 次（无效）
- ✅ 扩大场景数（有效）
- ⚠️ 若将来引入传感器噪声或随机初始位姿，执行层才会有方差，届时才需要 N 次重复
