## 1. 本阶段学习目标

### 1.1 一句话概括

第一阶段解决的是“让机器人向前走，遇到障碍就停”；第二阶段解决的是：

> **让机器人知道自己在哪里、应该朝哪个方向走，并且能沿这个方向走到指定位置。**

这句话拆开就是三件事：

1. **运动学**：左右轮速度怎样合成机器人整体的线速度和角速度。
2. **状态估计**：只用轮编码器，怎样估计机器人走了多远、转了多少。
3. **闭环控制**：有了目标方向和当前方向，怎样控制轮子把误差减小到零。

### 1.2 学完本阶段应具备的能力

- 【掌握】根据左右轮角速度计算 `v` 和 `ω`，也能反算左右轮目标速度。
- 【掌握】解释“右轮更快为什么向左转”“原地旋转为什么线速度为零”。
- 【掌握】用 `atan2` 计算目标航向，用角度归一化取最短转向路径。
- 【掌握】用左右轮编码器增量积分出位姿，并说明误差来源。
- 【掌握】实现指定角度转向、指定距离前进、单目标点导航。
- 【理解】Supervisor 真值与里程计估计的区别，以及为什么不能用控制器自报的 `reached` 代替验证。
- 【理解】基础规则式避障的能力边界。
- 【了解】为什么后续需要 PID、路径规划、SLAM 和传感器融合。

### 1.3 本阶段没有做的事情

明确边界，避免误解：

- 没有使用 ROS 2、SLAM、视觉、深度学习或 LLM Agent。
- 没有做全局定位。机器人不知道自己在地图上的绝对位置，里程计从 `(0,0,0)` 开始积分。
- 没有做路径规划。避障只是“停—转—走—恢复”的固定规则。
- 没有做动态障碍物、多目标点、曲线跟踪或速度平滑。

## 3. 差速驱动原理

### 3.1 先用直觉理解

差速驱动（differential drive）就像推购物车：

- 两个轮子转得一样快，车直着走。
- 右轮转得快一点，车头向左偏。
- 左轮转得快一点，车头向右偏。
- 两个轮子反着转，车原地打转。

它没有方向盘，转向完全由“左右轮的速度差”产生。这是本阶段最重要的直觉。

### 3.2 五种基本组合

设前进方向为正，`ωL` 是左轮角速度，`ωR` 是右轮角速度。

| 轮速关系 | 机器人运动 | 航向变化 | 实际例子 |
|---|---|---|---|
| `ωL = ωR > 0` | 直线前进 | 不变 | 两轮都给 4.0 rad/s |
| `ωL < ωR` | 向前并向左弯 | 增大（逆时针/CCW） | 左 1、右 3 |
| `ωL > ωR` | 向前并向右弯 | 减小（顺时针/CW） | 左 3、右 1 |
| `ωL = -ωR` | 原地旋转 | 正负由方向决定 | 左 -2、右 +2 向左转 |
| `ωL = 0, ωR > 0` | 绕左轮接触点画弧 | 增大 | 左轮刹住、右轮前进 |

把“左转”规定为正航向，是本项目的数学约定。它与 Webots 中绕 +Z 轴的逆时针旋转一致。[已实测]

### 3.3 为什么“右轮更快”是左转

想象你站在机器人后方往前看：

- 右轮走得快，右侧向前推得更多；
- 车身就会绕着一个瞬时中心向左偏；
- 从上方看，这是逆时针旋转，航向角增大。

反过来，左轮更快就是顺时针，航向角减小。

### 3.4 原地旋转为什么线速度为零

原地旋转时 `ωL = -ωR`：

```text
v = r(ωR + ωL) / 2 = r(ωR - ωR) / 2 = 0
```

两轮的线速度大小相等、方向相反，车体中心没有平动，只有转动。但角速度不为零：

```text
ω = r(ωR - ωL) / L = r(ωR - (-ωR)) / L = 2rωR / L
```

这就是“原地转”的数学解释。

### 3.5 实验观察

在本机 Webots 中实际观察到：

- 两轮同速：机器人沿 +X 直线前进，Supervisor 的 `y` 基本不变。
- 左轮 1、右轮 2：机器人向左前方画弧，航向增大。
- 左轮 2、右轮 1：机器人向右前方画弧，航向减小。
- 左 -2、右 +2：机器人原地逆时针旋转，位置几乎不变。

[已实测] 这些方向关系与公式一致，不是只从文档抄来的结论。

## 4. 运动学公式及推导

### 4.1 参数定义

| 符号 | 含义 | 单位 | 本机有效值 |
|---|---|---|---|
| `r` | 驱动轮半径 | m | 0.0200 |
| `L` | 左右轮接地点间距（轮距） | m | 0.058 |
| `ωL` | 左轮角速度 | rad/s | 控制量 |
| `ωR` | 右轮角速度 | rad/s | 控制量 |
| `v` | 车体中心线速度 | m/s | 计算量 |
| `ω` | 车体角速度 | rad/s | 计算量 |

注意：`r` 和 `L` 用的是“有效值”，不是照抄 e-puck 数据手册。原因见 6.4 节。

### 4.2 正运动学：轮速 → 车体速度

先算每个轮子接地点相对地面的线速度：

```text
vL = r · ωL
vR = r · ωR
```

车体中心的线速度是两轮线速度的平均值，因为车体是刚体，中心位于两轮中间：

```text
v = (vL + vR) / 2 = r(ωR + ωL) / 2
```

角速度来自两轮速度差。把机器人看成绕某个瞬时旋转中心（ICR）转动，左右轮到 ICR 的横向距离差为 `L`：

```text
vR - vL = ω · L
```

所以：

```text
ω = (vR - vL) / L = r(ωR - ωL) / L
```

符号约定：右轮更快时 `ωR > ωL`，`ω > 0`，对应逆时针/左转。

### 4.3 逆运动学：车体速度 → 轮速

已知想要的 `v` 和 `ω`，反解两轮速度：

```text
vL = v - ω·L/2
vR = v + ω·L/2
```

再除以轮半径：

```text
ω_left  = (v - ω·L/2) / r
ω_right = (v + ω·L/2) / r
```

代码里为了避免符号混淆，把 `L/2` 写成 `half_track`：

```python
half_track = wheel_base_m / 2.0
left = (linear_m_s - angular_rad_s * half_track) / wheel_radius_m
right = (linear_m_s + angular_rad_s * half_track) / wheel_radius_m
```

对应 `src/kinematics.py:65-77`。

### 4.4 代入本机参数算几个例子

有效参数：`r = 0.0200 m`，`L = 0.058 m`。

| 场景 | ωL | ωR | v = r(ωR+ωL)/2 | ω = r(ωR−ωL)/L | 解释 |
|---|---|---|---|---|---|
| 直线 | 4.0 | 4.0 | 0.080 m/s | 0 | 每秒前进 8 cm |
| 弧线 | 0 | 4.0 | 0.040 m/s | 1.379 rad/s | 绕左轮画弧 |
| 原地左转 | -2.0 | 2.0 | 0 | 1.379 rad/s | 约 1.14 s 转 90° |
| 原地右转 | 2.0 | -2.0 | 0 | -1.379 rad/s | 反方向 |
| 轻微左弯 | 1.0 | 3.0 | 0.040 m/s | 0.690 rad/s | 半径约 5.8 cm |

这些数字能帮助你建立“轮速—运动”的直觉。实际转向时间还会受到加速、采样周期和停止判断的影响，不能只用理论时间。

### 4.5 为什么轮距会影响转向速度

同样把右轮比左轮快 `Δω`：

```text
ω = r · Δω / L
```

`L` 越大，同样的速度差产生的角速度越小，转弯越“迟钝”。这就像用长杆划船，力臂越长，同样的力产生的角速度越小。

### 4.6 线速度与角速度的区别

| 概念 | 描述什么 | 单位 | 对应生活经验 |
|---|---|---|---|
| 线速度 `v` | 车体中心移动快慢 | m/s | 每秒走几米 |
| 角速度 `ω` | 车头转动快慢 | rad/s | 每秒转多少弧度 |

两者独立：可以“走得快但不转”，也可以“原地转但不走”。差速驱动用两个轮子同时控制这两个量，这也是它简单而强大的原因。

### 4.7 名义参数与有效参数

| 参数 | 名义值 | 本机有效值 | 差异原因 |
|---|---|---|---|
| 轮半径 `r` | 0.0205 m | 0.0200 m | 直线里程计偏高约 2.3% |
| 轮距 `L` | 0.052 m | 0.058 m | 原地旋转里程计偏高约 10% |

这不是说 e-puck 的物理尺寸变了，而是说：在“轮子与地面接触、存在轻微打滑、采样离散”的真实模型里，`0.0200` 和 `0.058` 能让里程计更接近 Supervisor 真值。它们应被理解为**有效标定参数**，换一个世界、地面或机器人时需要重新标定。

[已实测] 有效参数下，+90° 转向真值 1.5712 rad，−90° 为 −1.5712 rad，180° 为 3.1376 rad。

## 5. 坐标系和航向角

### 5.1 世界坐标系

本项目的 Webots 世界采用：

- X 轴：水平向右（在初始视角下）；
- Y 轴：水平向左；
- Z 轴：竖直向上；
- e-puck 初始朝向 +X；
- 偏航角（yaw）绕 +Z 轴，从 +X 转向 +Y 为正，即逆时针为正。

这解释了为什么目标点写成 `(0.8, 0.8)` 时机器人要向左前方走，写成 `(0.8, -0.8)` 时机器人要向右前方走。

### 5.2 机器人自身坐标系

| 机器人轴 | 指向 | 在本项目中的含义 |
|---|---|---|
| x | 车头前方 | 前进方向 |
| y | 车身左侧 | 左转方向 |
| z | 车顶上方 | 偏航轴 |

“机器人坐标系”会随车体转动；“世界坐标系”不动。导航时把目标点表示在世界坐标系，把机器人位姿也表示在世界坐标系，再计算差值，避免混用。

### 5.3 航向角与目标方位

目标方位角：

```python
desired = math.atan2(target_y - pose.y, target_x - pose.x)
```

它回答的是：“从当前位置指向目标，世界坐标系的 +X 轴需要逆时针转多少度？”

航向误差：

```python
error = normalize_angle(desired - pose.heading_rad)
```

- `error > 0`：目标在左侧，需要左转（增大航向）。
- `error < 0`：目标在右侧，需要右转（减小航向）。
- `error = 0`：正对目标。

### 5.4 弧度与角度

| 角度 | 弧度 |
|---|---|
| 30° | 0.5236 |
| 90° | 1.5708 |
| 180° | 3.1416 |
| 360° | 6.2832 |

Python 的 `math.atan2`、`math.sin`、`math.cos` 全部使用弧度。实验中输入角度用度（方便人读），进入控制前必须转成弧度：

```python
target_heading = math.radians(TARGET_ANGLE_DEG)
```

### 5.5 角度归一化

角度是周期量：`370°` 和 `10°` 是同一个方向。如果不归一化，控制器可能选择“绕远路”：

```text
目标 10°，当前 350°
直接相减：10 - 350 = -340°  → 看起来要顺时针转 340°
正确最短路径：+20°          → 逆时针转 20°
```

实现：

```python
def normalize_angle(angle_rad):
    return math.atan2(math.sin(angle_rad), math.cos(angle_rad))
```

`atan2(sin θ, cos θ)` 把任意角度映射到 `[-π, π]`，并且保留符号。对应 `src/kinematics.py:80-83`。

### 5.6 Supervisor 的偏航角提取

Webots 的 `getOrientation()` 返回一个 3×3 旋转矩阵，按行优先展开成 9 个数：

```text
[ R00 R01 R02
  R10 R11 R12
  R20 R21 R22 ]
```

本项目中机器人在 X–Y 平面内旋转，绕 Z 轴的偏航角为：

```python
yaw = math.atan2(orientation[3], orientation[0])  # atan2(R10, R00)
```

对应 `session_supervisor.py:49-55`。

为什么不是 `orientation[2]` 或 `orientation[1]`：

- `orientation[2] = R02`，描述的是 Z 方向的倾斜分量，不是平面偏航。
- `orientation[1] = R01 = -sin(yaw)`，直接拿来算会得到反号的航向。

这是本阶段调试成本最高的错误之一。错误的公式会让“左转”看起来像“右转”，从而把控制方向也带偏。

### 5.7 到达目标时的航向

导航的目标是“到达位置”，不是“到达位置并朝向某个方向”。因此控制器在距离进入容差后就停止，不再修正航向。实验中：

- 左目标点最终真值航向约 `+0.9827 rad`；
- 右目标点最终真值航向约 `-0.9827 rad`；
- 避障目标最终真值航向约 `-0.5040 rad`。

这些角度不是目标要求，而是“最后一次转向恰好停在这里”。如果下一阶段需要“到达后面向目标”，必须额外增加一个最终朝向控制步骤。

## 6. 轮式里程计原理

### 6.1 编码器读数是什么

e-puck 的 `left wheel sensor` / `right wheel sensor` 返回轮子关节的角位置，单位是弧度。控制器每个 `robot.step(32 ms)` 读取一次，做差得到这一小段时间内轮子转过的角度：

```text
ΔθL = encoderL_now - encoderL_prev
ΔθR = encoderR_now - encoderR_prev
```

再乘以轮半径，得到左右轮接地点走过的弧长：

```text
dL = r · ΔθL
dR = r · ΔθR
```

### 6.2 从轮位移到车体位姿

车体中心前进距离：

```text
ds = (dL + dR) / 2
```

航向变化：

```text
dθ = (dR - dL) / L
```

因为右轮走得多，车体向左转，`dθ > 0`，与第 4 节符号约定一致。

### 6.3 中点航向积分

如果直接用“转弯前的航向”去投影位移，走圆弧时会有偏差；用“转弯后的航向”也会偏。标准做法是用这一小步的中间航向：

```python
distance = (left_delta_m + right_delta_m) / 2.0
delta_heading = (right_delta_m - left_delta_m) / wheel_base_m
mid_heading = pose.heading_rad + delta_heading / 2.0
x = pose.x + distance * math.cos(mid_heading)
y = pose.y + distance * math.sin(mid_heading)
heading = normalize_angle(pose.heading_rad + delta_heading)
```

对应 `src/kinematics.py:103-125`，Webots 适配层在 `motion_controller.py:84-107` 调用它。

为什么用中点：一步之内航向从 `θ` 变到 `θ + dθ`，位移方向大约在两者中间。中点法是二阶近似，短步长下误差很小；步长越小越准，但计算量越大。

### 6.4 误差来源

| 来源 | 表现 | 本项目中的处理 |
|---|---|---|
| 轮子打滑 | 编码器转了，车没走那么多 | 用有效轮半径补偿平均效果 |
| 有效轮距误差 | 转同样的轮速差，实际转多/转少 | 标定 `L = 0.058` |
| 采样离散 | 每 32 ms 才更新一次 | 用中点积分减小偏差 |
| 编码器量化 | 极小位移读不出来 | 低速时误差占比更大 |
| 地面/负载变化 | 标定值漂移 | 换场景需重新标定 |
| 累计误差 | 时间越长，位置越偏 | 本阶段靠 Supervisor 事后验证；下一阶段需外部定位 |

### 6.5 为什么里程计不能代表真实位置

里程计是**航位推算**（dead reckoning）：从已知起点出发，把每一步的位移和转角累加。它没有“看外面”的传感器，无法知道：

- 轮子是否打滑；
- 是否被外力推动；
- 起点是否真的在 `(0,0)`；
- 车体是否因为碰撞而偏移。

所以它的误差会随时间累积。本阶段的三个目标点误差在 1.66–2.81 cm，看起来不大，但这是短距离、无碰撞、同一地面的结果，不能外推到长距离。

### 6.6 标定过程

1. 先用名义参数 `r = 0.0205`、`L = 0.052` 跑直线和旋转。
2. 直线：控制器认为走了 0.77 m，Supervisor 真值 0.7526 m，里程计偏高约 2.3%。
3. 旋转：控制器估计的转角比真值高约 10%。
4. 调整有效参数为 `r = 0.0200`、`L = 0.058`，重跑。
5. 复核：+90° 真值 1.5712 rad，−90° 真值 −1.5712 rad，180° 真值 3.1376 rad。

[已实测] 标定后的转向和距离结果明显改善；标定值只对当前世界、地面和机器人模型有效。

## 7. 转向控制方法

### 7.1 开环与闭环

| 方式 | 做法 | 问题 |
|---|---|---|
| 开环 | 转固定时间，比如“转 1 秒” | 电池、地面、负载变化都会让角度不准 |
| 闭环 | 每步读航向，误差小于容差就停 | 需要可靠的状态估计 |

本阶段用闭环：航向来自轮式里程计，目标来自输入角度。

### 7.2 控制逻辑

```python
target_heading = math.radians(TARGET_ANGLE_DEG)

while robot.step(timestep) != -1:
    pose = update_odometry()
    error = angle_error(target_heading, pose.heading_rad)

    if abs(error) <= HEADING_TOLERANCE_RAD:
        stop()
        return

    angular = SPIN_WHEEL_SPEED if error > 0 else -SPIN_WHEEL_SPEED
    left, right = wheel_velocities(0.0, angular, r, L)
    set_wheel_rad_s(left, right)
```

对应 `motion_controller.py:204-231`。

关键点：

- `wheel_velocities(0.0, angular, ...)` 的第一个参数是线速度 0，表示原地旋转。
- `error > 0` 时给正角速度，右轮更快，向左转；`error < 0` 时反过来。
- 每步重新计算误差，直到进入 5° 容差。
- 超时 22 s 会停止并报告 `timeout`，避免无限旋转。

### 7.3 为什么容差是 5°

控制循环每 32 ms 执行一次，旋转角速度 2.0 rad/s。一步内航向变化约：

```text
2.0 rad/s × 0.032 s = 0.064 rad ≈ 3.67°
```

也就是说，控制器每步至少“跨过”约 3.67°。如果容差小于这个步长，可能在目标两侧来回越过，形成抖动。5° 略大于一步的转角，是一个保守的折中。

### 7.4 实际转向结果

| 目标 | 实测航向 | 误差 | 结论 |
|---|---|---|---|
| 左转 90° | +1.5712 rad | +0.0004 rad（约 0.02°） | 通过 |
| 右转 90° | −1.5712 rad | −0.0004 rad | 通过 |
| 原地 180° | 3.1376 rad | −0.0040 rad（约 −0.23°） | 通过 |
| 小角度 30° | 0.4591 rad | −0.0645 rad（约 −3.70°） | 在 5° 容差内，但接近一步分辨率 |

[已实测] 90° 和 180° 的结果很好；30° 偏小 3.7°，不是公式错误，而是“一步 3.67° + 5° 容差”共同造成的量化效应。这也说明：**容差不是越小越好**，要和采样周期、角速度一起设计。

### 7.5 改进方向（本阶段未实现）

- 接近目标时降低角速度（分段或比例控制），减小一步跨过的角度。
- 使用 `ω = clamp(kp * error, -ωmax, ωmax)` 的比例控制。
- 增加最小速度死区，避免电机在极小误差下不转。
- 用 Supervisor/GPS/IMU 做外部校验，而不是把真值喂进控制器。

## 8. 指定距离运动

### 8.1 控制逻辑

```python
if abs(odometry.distance_m) >= TARGET_DISTANCE_M - POSITION_TOLERANCE_M:
    stop()
    return

set_wheel_rad_s(left, right, MAX_WHEEL_SPEED, MAX_WHEEL_SPEED)
```

对应 `motion_controller.py:174-202`。

这里用的是**累计路程** `odometry.distance_m`，不是位移向量长度。直线前进时两者近似相等；如果中途转弯，累计路程会大于直线距离，所以这个模式只用于“从静止直线前进”的实验。

### 8.2 为什么会有系统性欠走

控制器在 `distance >= target - 0.02` 时就停，因此理论上就会少走约 2 cm。再加上：

- 每步 32 ms，速度 0.08 m/s，一步约 2.56 mm；
- 停止判断在运动之后，存在一步左右的延迟；
- 轮子减速、地面摩擦和打滑。

最终真值通常比目标少 1.6–2.0 cm，属于“设计容差 + 执行延迟”的结果，不是随机故障。

### 8.3 实际距离结果

| 目标距离 | 控制器里程计 | 实测距离（当次记录） | 误差 |
|---|---|---|---|
| 0.25 m | 约 0.230 m | 0.2304 m | −0.0196 m（1.96 cm） |
| 0.50 m | 约 0.481 m | 0.48128 m | −0.01872 m（1.87 cm） |
| 0.80 m | 约 0.783 m | 0.78336 m | −0.01664 m（1.66 cm） |

[已实测] 三组距离都在约 2 cm 内；数据来自本阶段标定后的实际运行记录。注意：这三组距离实验的独立日志没有像导航实验那样单独保存，复现实验时应重新运行并保存日志。

### 8.4 容差怎么选

| 容差 | 效果 | 风险 |
|---|---|---|
| 0.04 m | 停得更早，真值误差约 3.7–4.05 cm | 精度不足 |
| 0.02 m | 真值误差约 1.7–2.0 cm | 本阶段采用 |
| 0.01 m | 可能更准 | 容易因一步 2.56 mm 的量化而抖动或超时 |

容差不是“越小越厉害”，它必须和传感器分辨率、控制周期、机械响应匹配。

## 9. 目标点导航逻辑

### 9.1 算法：转向—前进—再判断

本阶段采用最简单的“turn-then-drive”控制器：

```text
循环：
  1. 用里程计更新当前位姿 (x, y, θ)
  2. 计算到目标点的距离 d
  3. 如果 d <= 0.02 m：停止，报告 reached
  4. 计算目标方位 desired = atan2(dy, dx)
  5. 计算航向误差 e = angle_error(desired, θ)
  6. 如果 |e| > 5°：原地转向（正误差左转，负误差右转）
  7. 否则：两轮同速前进
  8. 如果前方传感器 > 120：停止或进入避障
  9. 如果时间 > 22 s：停止，报告 timeout
```

对应 `motion_controller.py:239-305`。

这不是“边走边平滑修方向”的控制器，而是“先对准、再直走”的 bang-bang 控制。优点是逻辑清楚、容易调试；缺点是路径由“转向—直走”拼接而成，不是最短平滑路径。

### 9.2 为什么每步都要重新计算

机器人并不是完美直线运动：左右轮打滑、地面不均、转向停止有延迟，都会让航向慢慢偏。每步重算 `desired` 和 `error`，相当于不断修正，而不是“出发时算一次就闭眼走”。

### 9.3 三个方向的目标点

测试覆盖了三种情况，避免只验证“正前方”：

| 目标点 | 需要的动作 | 控制器结果 | Supervisor 真值 | 真值误差 |
|---|---|---|---|---|
| (0.8, 0.0) | 直走 | `distance=0.018` | (0.78336, 0.00000) | 1.66 cm |
| (0.8, 0.8) | 左转约 45° 后走 | `distance=0.018` | (0.77439, 0.80255) | 2.57 cm |
| (0.8, −0.8) | 右转约 45° 后走 | `distance=0.018` | (0.77437, −0.80255) | 2.58 cm |

[已实测] 三组都到达了目标区域。日志文件：

```text
webots/logs/stage2_nav_straight.log
webots/logs/stage2_nav_straight_supervisor.log
webots/logs/stage2_nav_left.log
webots/logs/stage2_nav_left_supervisor.log
webots/logs/stage2_nav_right.log
webots/logs/stage2_nav_right_supervisor.log
```

### 9.4 控制器说“到了”不等于真的到了

三组日志里控制器都输出：

```text
RESULT: reached ... distance=0.018
```

但 Supervisor 真值到目标的距离分别是 1.66 cm、2.57 cm、2.58 cm。原因：

- 控制器用的是自己的里程计位姿，里程计有误差；
- `distance=0.018` 是“里程计认为的距离”，不是“真实距离”；
- 停止时机器人还有一点惯性，真正停稳的位置会再偏一点。

所以本阶段的验收规则是：

> **必须读取 Supervisor 的最终 `(x, y)`，计算它到目标点的欧氏距离，不能只看控制器的 `reached`。**

本阶段采用的工程判据是“真实位置距目标 ≤ 3 cm”。三组导航和避障都满足；这是本项目自定的判据，不是任务书给定的官方阈值。

### 9.5 超时与安全停止

| 情况 | 行为 | 日志 |
|---|---|---|
| 到达 | 两轮速度 0 | `RESULT: reached ...` |
| 超时 22 s | 两轮速度 0 | `RESULT: timeout ...` |
| 前方障碍 | 停止或进入避障 | `AVOID` / `RESULT: blocked` |
| 设备缺失 | 抛异常 | `RESULT: error ...` |

安全停止的原则：任何异常分支都必须先 `setVelocity(0)`，不能“报个错然后继续跑”。

## 10. 基础障碍物处理

### 10.1 规则

本阶段的避障不是路径规划，而是一个固定的“停—左转—前进—恢复”状态机：

```text
正常导航
  │ front > 120 且距上次避障 > 1.5 s
  ▼
停车 → 左转 1.0 s → 直走 1.2 s → 恢复导航
```

对应 `motion_controller.py:273-293`。

参数：

| 参数 | 值 | 作用 |
|---|---|---|
| `PS_STOP_THRESHOLD` | 120.0 | 前方距离传感器触发阈值 |
| 左转时长 | 1.0 s | 以 2 rad/s 约转 2 rad（约 115°） |
| 前进时长 | 1.2 s | 以 0.08 m/s 约走 9.6 cm |
| 冷却时间 | 1.5 s | 防止刚恢复就立刻重复触发 |

### 10.2 为什么选择左转

这是最简单的固定策略：障碍物在正前方，左转可以绕到它的上方。右转也可能成功，但本阶段只验证了左转。代码没有根据目标在左还是在右来选择方向，也没有“哪边空间更大”的判断。

### 10.3 实际轨迹

障碍物：`Solid` 立方体，中心 `(0.45, 0, 0)`，边长 0.12 m。机器人从 `(0,0)` 出发，目标 `(0.8, 0)`。

实际日志（`webots/logs/stage2_obstacle.log`）：


### 10.4 能力边界

| 能做到 | 不能做到 |
|---|---|
| 检测正前方障碍并停下 | 识别障碍物形状、大小、位置 |
| 用固定动作尝试绕开 | 规划最短或最优路径 |
| 绕开后恢复目标方向 | 保证在复杂环境中一定成功 |
| 记录避障事件 | 处理动态障碍、狭窄通道、死角 |

因此本阶段把避障标记为“基础尝试/部分通过”，而不是“完整避障”。任务书也只要求基础规则式避障，不要求路径规划。

### 10.5 多障碍扩展实验（新增）

为了直观回答“能不能多次避障”，新增 `worlds/stage2_multi_obstacle.wbt`：2.4×2.4 m 场地、3 个 0.18 m 障碍、目标 `(1.0, 0)`、近距离视角。实测：

| 版本 | 第三个障碍 y | AVOID 次数 | Supervisor 真值终点 | 真值误差 |
|---|---|---|---|---|
| v1 | −0.02 | 2 | (0.97307, 0.07107) | 7.6 cm |
| v2 | 0.05 | 3 | (0.97035, 0.11641) | 12.0 cm |

结论：**固定左转规则可以连续触发多次避障**；v2 确实触发了 3 次。但每多一次避障，航向/里程计误差会累积，最终真值误差从单障碍的 2.81 cm 退化到 7.6–12.0 cm。也就是说，“能重复避障”不等于“能稳定精确到达”。这个世界的用途是观察多次触发，精度验收仍用 `stage2_lab.wbt` / `stage2_obstacle.wbt`。

## 11. 关键 Python 代码逐段解释

### 11.1 正运动学

`src/kinematics.py:44-62`：

```python
def differential_drive(left_rad_s, right_rad_s, wheel_radius_m, wheel_base_m):
    _validate_geometry(wheel_radius_m, wheel_base_m)
    linear = wheel_radius_m * (right_rad_s + left_rad_s) / 2.0
    angular = wheel_radius_m * (right_rad_s - left_rad_s) / wheel_base_m
    return RobotVelocity(linear_m_s=linear, angular_rad_s=angular)
```

解释：

- 先检查 `r > 0`、`L > 0`，避免除零和负半径。
- `linear` 是两轮线速度的平均。
- `angular` 是两轮线速度差除以轮距。
- 返回不可变的 `RobotVelocity`，避免调用方误改。

### 11.2 逆运动学

`src/kinematics.py:65-77`：

```python
half_track = wheel_base_m / 2.0
left = (linear_m_s - angular_rad_s * half_track) / wheel_radius_m
right = (linear_m_s + angular_rad_s * half_track) / wheel_radius_m
```

解释：

- 想左转（`angular > 0`）时，左轮减、右轮加。
- `half_track` 是轮距的一半，来自绕车体中心的力臂。
- 返回值是左右轮角速度，单位 rad/s。

### 11.3 角度工具

`src/kinematics.py:80-89`：

```python
def normalize_angle(angle_rad):
    return math.atan2(math.sin(angle_rad), math.cos(angle_rad))

def angle_error(target_rad, current_rad):
    return normalize_angle(target_rad - current_rad)
```

解释：

- `normalize_angle` 把任意角度折到 `[-π, π]`。
- `angle_error` 直接给出“从当前转到目标”的最短有符号角。
- 不要把 `angle_error` 写成简单的 `target - current`，否则 350°→10° 会转 340°。

### 11.4 目标方位

`src/kinematics.py:92-100`：

```python
def heading_to_target(current_x, current_y, target_x, target_y):
    return math.atan2(target_y - current_y, target_x - current_x)
```

解释：

- `atan2(dy, dx)` 自动处理四个象限。
- 不要用 `atan(dy/dx)`，因为它在 `dx = 0` 时除零，而且无法区分象限。

### 11.5 位姿积分

`src/kinematics.py:103-125`：

```python
distance = (left_delta_m + right_delta_m) / 2.0
delta_heading = (right_delta_m - left_delta_m) / wheel_base_m
mid_heading = pose.heading_rad + delta_heading / 2.0
return Pose(
    x=pose.x + distance * math.cos(mid_heading),
    y=pose.y + distance * math.sin(mid_heading),
    heading_rad=normalize_angle(pose.heading_rad + delta_heading),
)
```

解释：

- `distance` 是车体中心前进的弧长。
- `delta_heading` 是这一小步的转角。
- 用 `mid_heading` 投影，减小圆弧误差。
- 最后对航向归一化，防止角度无限增长。

### 11.6 Webots 里程计适配

`motion_controller.py:84-107`：

```python
left_delta = (left_value - self.previous_left) * WHEEL_RADIUS_M
right_delta = (right_value - self.previous_right) * WHEEL_RADIUS_M
self.previous_left = left_value
self.previous_right = right_value
self.distance_m += (left_delta + right_delta) / 2.0
self.pose = advance_pose(self.pose, left_delta, right_delta, WHEEL_BASE_M)
```

解释：

- 第一帧只记录初值，不积分，避免把“从 0 开始的绝对读数”当成位移。
- 用有符号增量，倒车时也能正确积分。
- `distance_m` 是累计路程，用于“指定距离”模式。
- 位姿 `pose` 用于“转向”和“导航”模式。

### 11.7 转向模式

`motion_controller.py:204-231`：

```python
error = angle_error(target_heading, pose.heading_rad)
if abs(error) <= HEADING_TOLERANCE_RAD:
    stop(left_motor, right_motor)
    return 0
angular = SPIN_WHEEL_SPEED if error > 0 else -SPIN_WHEEL_SPEED
left, right = wheel_velocities(0.0, angular, WHEEL_RADIUS_M, WHEEL_BASE_M)
set_wheel_rad_s(left_motor, right_motor, left, right)
```

解释：

- 先判断是否到达容差，再决定转向，避免“到了还继续转”。
- 角速度方向由误差符号决定。
- 线速度为 0，保证原地旋转。

### 11.8 导航模式

`motion_controller.py:239-305`：

```python
distance = math.hypot(target[0] - pose.x, target[1] - pose.y)
desired = heading_to_target(pose.x, pose.y, target[0], target[1])
error = angle_error(desired, pose.heading_rad)
front = front_value()

if distance <= POSITION_TOLERANCE_M:
    stop(...)
    return 0

if abs(error) > HEADING_TOLERANCE_RAD:
    angular = SPIN_WHEEL_SPEED if error > 0 else -SPIN_WHEEL_SPEED
    left, right = wheel_velocities(0.0, angular, WHEEL_RADIUS_M, WHEEL_BASE_M)
else:
    set_wheel_rad_s(left_motor, right_motor, MAX_WHEEL_SPEED, MAX_WHEEL_SPEED)
```

解释：

- 距离判断优先于转向：只要进入 2 cm，就停止，不再管航向。
- 航向误差大时原地转，误差小时直走。
- 每步都重新计算，具有反馈修正能力。
- 这一段同时被 `navigate` 和 `avoid` 复用，`avoid` 只是在前面插入状态机。

### 11.9 Supervisor 真值

`session_supervisor.py:49-55`：

```python
orientation = robot_node.getOrientation()
yaw = math.atan2(orientation[3], orientation[0])
log(f"POSE t={now:.2f} pos={robot_node.getPosition()} yaw={yaw:.4f} ori={orientation}")
```

解释：

- `getPosition()` 返回真实三维位置。
- `getOrientation()` 返回旋转矩阵，按行优先取 `R10` 和 `R00` 算偏航。
- 每 0.5 s 记录一次，最后一条就是停稳后的真值。
- Supervisor 不参与控制，只做验证和限时退出。

`tests/test_kinematics.py` 覆盖：

- 右轮快 → 正角速度；
- 左轮快 → 负角速度；

## 13. Supervisor 与里程计误差对比

### 13.1 导航与避障对比

| 场景 | 控制器里程计终点 | Supervisor 真值终点 | 目标 | 真值到目标距离 | 里程计/真值航向 |
|---|---|---|---|---|---|
| 正前方 | (0.782, 0.000) | (0.78336, 0.00000) | (0.8, 0.0) | 1.66 cm | 0 / 0 |
| 左前方 | (0.790, 0.785) | (0.77439, 0.80255) | (0.8, 0.8) | 2.57 cm | 0.959 / 0.9827 |
| 右前方 | (0.790, −0.785) | (0.77437, −0.80255) | (0.8, −0.8) | 2.58 cm | −0.959 / −0.9827 |
| 避障 | (0.784, 0.009) | (0.77745, −0.01687) | (0.8, 0.0) | 2.81 cm | −0.448 / −0.5040 |

### 13.2 三个误差要分开看

1. **控制器报告的 `distance`**：里程计估计的“到目标距离”，例如 0.018 m。
2. **里程计位姿与真值的差**：反映状态估计误差，例如左前方约 2.35 cm。
3. **真值到目标的距离**：反映最终任务完成度，例如左前方 2.57 cm。

三者不是同一个数。只报第 1 个，会让人误以为“误差只有 1.8 cm”；只报第 2 个，也不能说明任务是否完成。工程报告应同时给出第 2 和第 3 个。

### 13.3 为什么左/右目标误差比正前方大

- 正前方不需要大角度转向，航向误差小，路径接近直线。
- 左/右目标要先转约 45°，转向停止有量化误差，之后直走会把航向误差放大成横向偏移。
- 里程计的轮距/轮半径标定误差在转弯后更明显。
- 停止条件是“里程计距离 ≤ 2 cm”，不是“真实距离 ≤ 2 cm”，所以真值误差会更大。

### 13.4 验收判据

本阶段采用的工程判据：

- 真实位置到目标 ≤ 3 cm；
- 控制器必须报告 `reached`；
- 不能出现 `timeout`、`blocked`（避障场景除外）或 `error`；
- 运行结束后无残留 Webots/Python 进程。

四个导航/避障场景全部满足。这个 3 cm 是本项目自定的工程判据，不是任务书规定的硬 threshold；如果后续要求更高精度，需要更小的停止半径、更低的速度和更好的定位。

## 14. 常见错误及排查方法

### 14.1 航向公式取错矩阵元素

**现象**：机器人明明左转，Supervisor 记录的 yaw 却是负的；或者转了 90°，yaw 仍接近 0。

**原因**：用了 `orientation[2]` 或 `orientation[1]`。

**修复**：`yaw = atan2(orientation[3], orientation[0])`。

**验证**：手动左转 90°，看 yaw 是否约 +1.57。

### 14.2 假设前进方向是 −Z

**现象**：目标点在 `(0.8, 0.8)`，机器人却往别处走；Supervisor 显示 x 增加、z 不变。

**原因**：套用了其他机器人/其他世界的坐标约定。

**修复**：以本世界的实测为准：e-puck 前进 +X，平面是 X–Y，yaw 绕 +Z。

### 14.3 角度不归一化

**现象**：目标在 10°，机器人却顺时针转一大圈；或者航向数值越来越大。

**原因**：直接相减，没有取最短路径。

**修复**：`normalize_angle(target - current)`。

### 14.4 转向符号反了

**现象**：目标在左，机器人向右转，越走越远。

**原因**：`error > 0` 时给了负角速度，或 `wheel_velocities` 左右写反。

**修复**：记住“正误差 = 左转 = 右轮更快 = 正角速度”。

### 14.5 直接用名义轮距，不标定

**现象**：转 90° 实际转了约 99°，或者直线走 0.77 m 实际只有 0.75 m。

**原因**：轮子打滑、接触几何与名义值不同。

**修复**：用 Supervisor 真值标定有效 `r` 和 `L`；换场景重新标定。

### 14.6 用固定时间控制

**现象**：同一段代码，有时转 88°，有时转 95°。

**原因**：电池、地面、负载、加速时间变化。

**修复**：用编码器/航向闭环，不用 `sleep` 或固定步数。

### 14.7 停止容差太大

**现象**：导航真值误差 3.7–4.05 cm。

**原因**：`POSITION_TOLERANCE_M = 0.04`。

**修复**：收紧到 0.02 m，并接受约 1.7–2.0 cm 的系统性欠走。

### 14.8 证据日志被覆盖

**现象**：报告里引用的“避障日志”实际是右方向导航日志。

**原因**：运行脚本每次写同一个 `motion_controller.log`，运行结束后没有立即另存；批量命令的顺序又把后一次运行复制成了前一次的名字。

**修复**：每次实验结束后立刻 `cp` 到带场景名的文件；引用前用 `grep` 检查关键行（如 `AVOID`、目标坐标）是否匹配。

**本项目的真实教训**：第一次保存的 `stage2_obstacle.log` 内容是 `target=(0.8,-0.8)`，不是避障场景。后来重新运行 `avoid`，立即保存，并确认日志含两次 `AVOID` 和 `target=(0.8,0.0)`。

### 14.9 合并日志时先看到 Supervisor 的 `RESULT`

**现象**：想抓控制器的 `RESULT`，却抓到 `RESULT: session_timeout`。

**原因**：两份日志拼在一起时，Supervisor 的超时行先出现。

**修复**：按文件分别 `grep`，或用 `grep "RESULT: reached"` / `grep "RESULT: blocked"` 精确过滤。

### 14.10 WSL 输出出现乱码/NUL

**现象**：`wsl.exe ... | tail` 输出二进制或乱码。

**原因**：Windows/WSL 互操作输出编码不一致。

**修复**：`... 2>&1 | tr -d '\000'`，或先写入 UTF-8 文件再读。

### 14.11 没有 pytest

**现象**：`.venv/bin/python -m pytest` 报 `No module named pytest`。

**原因**：项目使用标准库 `unittest`，没有安装 pytest。

**修复**：`.venv/bin/python -m unittest discover -s tests -v`。

### 14.12 运行结束仍有 Webots/Python 进程

**现象**：下一次运行时端口/文件被占用，或日志混入上一次内容。

**原因**：Webots 没有正常退出，或脚本被中断。

**修复**：运行器启动前和结束后都清理 `*webots*`、`python*` 进程；Supervisor 25 s 强制 `simulationQuit(0)`。

## 15. 知识点之间的联系

### 15.1 一条完整的因果链

```text
轮半径/轮距
   │ 决定
   ▼
正/逆运动学 ──→ 轮速与车体速度的换算
   │
   ▼
编码器增量 ──→ 位姿积分 ──→ 里程计位姿
   │                         │
   │                         ├──→ 转向控制（航向误差）
   │                         ├──→ 距离控制（累计路程）
   │                         └──→ 目标点导航（距离 + 方位）
   │
   ▼
Supervisor 真值 ──→ 误差分析 ──→ 参数标定 ──→ 回到运动学
```

### 15.2 每个概念依赖什么、被谁使用

| 概念 | 依赖 | 被谁使用 | 如果出错会怎样 |
|---|---|---|---|
| 差速运动学 | `r`、`L`、轮速 | 转向、导航、里程计 | 转向方向/速度不对 |
| 航向角 | 坐标系、`atan2` | 转向、导航 | 目标方向判断错 |
| 角度归一化 | 三角函数 | 转向、导航 | 绕远路、抖动 |
| 里程计 | 编码器、`advance_pose` | 距离、转向、导航 | 位置/航向漂移 |
| 标定 | Supervisor 真值 | 所有闭环控制 | 系统性偏差 |
| 闭环控制 | 状态估计、容差 | 转向、距离、导航 | 超时、振荡、到不了 |
| 避障 | 距离传感器、导航 | 最终任务 | 撞障碍或卡死 |
| Supervisor | Webots API | 验证、标定 | 无法证明任务完成 |

### 15.3 三个“看起来一样、其实不同”的量

| 量 | 来源 | 用途 | 常见误用 |
|---|---|---|---|
| 轮速 `ωL/ωR` | 控制器设定 | 驱动电机 | 把它当成车体角速度 |
| 车体角速度 `ω` | 运动学计算 | 理论分析 | 忘了它和轮速差成正比 |
| 航向角 `θ` | 里程计积分 | 控制反馈 | 把它和“目标方位”混为一谈 |

### 15.4 为什么先做运动学，再做导航

如果运动学符号错了，导航会表现为“目标在左，车往右”，你会以为是导航算法错；如果里程计标定错了，导航会表现为“每次都差几厘米”，你会以为是容差问题。先把底层公式和标定做对，后续调试才有意义。这也是任务书要求“严格按顺序推进”的原因。

## 16. 动手练习

### 练习 1：手算正/逆运动学

取 `r = 0.0200`、`L = 0.058`，计算：

1. `ωL = 1.0`、`ωR = 3.0` 时的 `v` 和 `ω`。
2. 想要 `v = 0.05 m/s`、`ω = 1.0 rad/s` 时的 `ωL` 和 `ωR`。
3. 想原地以 1.0 rad/s 左转时的 `ωL` 和 `ωR`。

参考答案：

1. `v = 0.0200 × (3+1)/2 = 0.040 m/s`；`ω = 0.0200 × (3−1)/0.058 ≈ 0.690 rad/s`。
2. `half_track = 0.029`；`ωL = (0.05 − 1.0×0.029)/0.02 = 1.05 rad/s`；`ωR = (0.05 + 0.029)/0.02 = 3.95 rad/s`。
3. `ωL = −(1.0×0.029)/0.02 = −1.45 rad/s`；`ωR = +1.45 rad/s`。

### 练习 2：观察转向量化

把 `SPIN_WHEEL_SPEED` 从 2.0 改成 1.0，重跑 30° 转向。预测并且记录：

- 一步转过的角度变成多少？
- 实际停止角度更接近 30° 还是更远？
- 转向时间变长多少？

提示：一步转角 = `ω × 0.032`。速度减半，量化误差减半，但耗时加倍。

### 练习 3：改变位置容差

### 练习 4：增加第四个目标点

- 需要转多少度？
- 真值误差多少？
- 是否在 22 s 内完成？

提示：`(-0.5, 0.5)` 需要约 135° 转向，能检验大角度导航。

### 练习 6：给圆弧积分写测试

## 17. 自测题与答案解析

### 题目

1. 为什么左右轮同速时机器人走直线？
2. 为什么右轮更快时机器人向左转？
3. 为什么原地旋转时线速度为 0，但角速度不为 0？
4. `robot.step(32)` 的 32 表示什么？为什么控制循环要和它一致？
5. 为什么角度要归一化？不归一化会出什么问题？
6. 为什么里程计积分要用中点航向？
7. 里程计的误差来源有哪些？为什么它不能代替真实位置？
8. 为什么不能只看控制器的 `reached` 判断导航成功？
9. 控制器报告 `distance=0.018`，Supervisor 真值误差却是 2.57 cm，这两个数矛盾吗？
10. 为什么 30° 转向会差 3.7°？这是 bug 吗？
11. 基础避障为什么只能算“尝试”，不能算“完整避障”？
12. 如果要把精度提高到 1 cm，需要改哪些地方？

### 答案与解析

1. 两轮线速度相等，车体中心速度是两者平均，角速度是差值除以轮距，差值为 0，所以只有平动。
2. 右轮线速度更大，车体绕瞬时中心逆时针偏转；从上方看航向增大，即左转。
3. 两轮线速度大小相等、方向相反，平均为 0；但速度差不为 0，除以轮距得到非零角速度。
4. 32 是 Webots 的基本时间步，单位毫秒；`step(32)` 让仿真推进 32 ms。控制循环按同一节拍读传感器、算控制、设电机，保证时序一致。
5. 角度是周期量；不归一化会把 350°→10° 算成 −340°，导致绕远路或振荡。`atan2(sin, cos)` 把角度折到 `[-π, π]`。
6. 一步内航向在变化，位移方向大约在起始和结束航向之间；用中点投影是二阶近似，比用起点或终点更准。
7. 轮滑、有效半径/轮距误差、采样离散、编码器量化、地面变化、碰撞、累计漂移。它没有外部绝对参考，误差会随时间累积。
8. `reached` 用的是控制器自己的里程计，里程计有误差；只有 Supervisor 的真实位姿才能证明机器人真的在目标区域。
9. 不矛盾。0.018 是里程计估计的到目标距离；2.57 cm 是真实位置到目标的距离。两者相差约 0.8 cm，正是里程计误差的体现。
10. 不是 bug。旋转速度 2 rad/s、步长 32 ms，一步约 3.67°；5° 容差只比一步略大，停止时可能少走接近一个步长。要更准，需降低接近目标时的角速度或改用比例控制。
11. 它只按固定规则左转、前进、恢复，不建图、不规划、不记忆障碍，遇到复杂形状/狭窄通道/动态障碍可能失败；任务书也只要求基础规则式避障。
12. 减小并动态调整接近速度、使用比例/PID 控制、提高编码器分辨率或加 IMU、做更细的轮半径/轮距标定、使用外部定位（GPS/视觉/SLAM）、把停止判据从里程计改为更可靠的状态估计。仅把容差改成 0.01 不够。

### 18.2 当前不足

- 导航是“转向—直走”的 bang-bang 控制，不是平滑轨迹；没有速度规划，起停有冲击。
- 没有全局定位，长距离会漂移；没有地图，避障无记忆。
- 避障只验证了一个固定场景，换障碍位置/尺寸/走廊可能失败。
- 转向和距离实验的独立日志没有全部归档，复现性还可以更好。
- 控制器里还有少量未使用的导入/常量（技术债），不影响功能，但应清理。
- Webots 场景测试还没有完全自动化成“一键跑完所有用例并断言”的脚本。
- 多障碍扩展实验证明固定左转可以连续触发，但真值误差会随避障次数累积到 7.6–12.0 cm，尚不能作为精度场景。
